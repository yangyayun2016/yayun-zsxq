# 从Switchback到Scenario Modeling：亚马逊正在把运营决策变成“可计算的实验”

这张图透露的不是一个普通新工具，而是亚马逊决策系统的一次升级：

> 从“告诉卖家发生了什么”，升级为“在执行前预测不同策略可能产生什么结果”。

亚马逊已经建立名为 [Scenario Modeling（场景建模）](https://sellercentral.amazon.com/help/hub/reference/external/GKE994FS8DQVAU5V) 的Seller Central官方帮助页面。该功能可能仍处于分账户、分功能逐步开放阶段。

## 一、先区分三个概念

| 方法 | 发生阶段 | 是否真正改变业务 | 解决的问题 |
|---|---

这张图和前面的 Switchback 放在一起，形成了一套更完整的新思路：

> Amazon正在从“提供经营数据”升级为“预测决策结果”，再通过真实实验验证预测，最终形成自动优化闭环。

官方已经建立 [Scenario Modeling帮助页面](https://sellercentral.amazon.com/help/hub/reference/external/GKE994FS8DQVAU5V)。从截图来看，该功能可能仍处于分批开放阶段。

## 一、先区分两个概念

| 对比维度 | Scenario Modeling | Switchback Experiment |
|----|----|----|
| 中文理解 | 场景模拟、决策沙盘 | 时间切换实验 |
| 发生时间 | 执行决策之前 | 决策执行过程中 |
| 是否改变真实业务 | 模拟本身不改变 | 会真实改变商品状态 |
| 核心问题 | 如果这样做，可能发生什么？ | 变化是否真由这个策略造成？ |
| 方法 | 预测模型、数字孪生、情景推演 | 随机化、时间切换、因果推断 |
| 输出 | 预测结果和方案比较 | 真实处理效应 |
| 主要风险 | 模型预测不准确 | 残留效应、实验成本 |

所以，Scenario Modeling不是Switchback，但两者可以组成完整闭环：

```
flowchart LR
    A["历史经营数据"] --> B["场景预测"]
    B --> C["小范围实验"]
    C --> D["策略执行"]
    D --> E["实际结果复盘"]
    E --> B
```

## 二、截图透露出的Amazon发展方向

Amazon过去的工具主要回答三个问题：

1. 发生了什么；

2. 为什么发生；

3. 建议卖家做什么。

Scenario Modeling开始回答第四个问题：

> 如果我改变价格、广告、库存、仓储或包装方案，未来可能发生什么？

截图提到的场景包括：

* 库存分配变化；

* 广告支出变化；

* 定价策略变化；

* FBA与AWD之间的库存配置；

* 加入Amazon Warehousing and Distribution；

* 加入SIPP自有包装发货；

* 不同供应链策略；

* 新Amazon计划对整体盈利能力的影响。

但需要区分“当前已经开放”和“未来发展方向”。

从截图正文可以直接确认的当前示例主要是：

* 将符合条件的商品注册到AWD；

* 将符合条件的商品加入SIPP；

* 比较采用这些方案后的影响。

广告、价格和更复杂的供应链模拟更像平台对Scenario Modeling的整体能力描述。截图同时表示，Amazon将在未来几个月推出更多行动。因此不能默认所有账号现在已经可以模拟广告和价格。

## 三、Amazon正在建立“卖家经营数字孪生”

这项功能的本质不是普通计算器，而是给每个商品建立一个简化的“数字副本”。

数字副本中可能包含：

* 商品历史销量；

* 季节性和需求预测；

* 当前FBA库存；

* AWD库存；

* 补货周期；

* 物流和仓储费用；

* 商品尺寸与重量；

* 价格；

* 广告支出；

* 促销安排；

* 退货和退款；

* 商品毛利；

* 缺货风险；

* Amazon计划资格。

卖家改变一个或多个变量后，系统重新计算未来结果。

例如：

| 场景 | 决策变量 | 预测结果 |
|----|----|----|
| 基准场景 | 保持现状 | 原始利润、库存和缺货风险 |
| 场景A | 30%库存放入AWD | 仓储成本、补货效率、缺货概率 |
| 场景B | 加入SIPP | 包装费用、配送成本、商品资格 |
| 场景C | FBA库存提高20% | 库存周转、低库存费、仓储费 |
| 场景D | AWD+SIPP组合 | 总成本、利润和供应链稳定性 |

真正高级的系统不会只给一个预测数字，而应输出：

* 保守情景；

* 基准情景；

* 乐观情景；

* 预测置信区间；

* 最坏结果；

* 触发风险的临界值。

## 四、对天机AI系统最有价值的启发

可以把它升级为一个“亚马逊经营决策实验室”，而不仅是报表分析系统。

### 第一层：经营基线模型

先计算ASIN当前真实状态：

* 销量；

* 销售额；

* 广告订单与自然订单；

* CPC、CVR、ACOS、TACOS；

* 单件贡献利润；

* 库存周转天数；

* FBA、AWD与在途库存；

* 缺货概率；

* 仓储、配送、退货和促销成本。

### 第二层：场景变量引擎

让用户选择准备改变什么：

* 售价提高或降低；

* Coupon、BD或Prime折扣；

* 广告预算增减；

* CPC和广告位调整；

* 核心词排名目标；

* FBA与AWD库存比例；

* 补货数量和时间；

* 加入SIPP；

* Listing图片、标题或卖点升级；

* 新增产品或变体；

* 竞争对手降价、涨竞价或做促销。

### 第三层：预测模型

分别计算：

预测销量=基础需求×价格影响×广告影响×排名影响×库存可售率×季节系数预测销量 = 基础需求 \	imes 价格影响 \	imes 广告影响 \	imes 排名影响 \	imes 库存可售率 \	imes 季节系数预测利润=预测销售额−产品成本−平台佣金−履约费用−仓储费用−广告费用−促销费用−退货损失预测利润 = 预测销售额 - 产品成本 - 平台佣金 - 履约费用 - 仓储费用 - 广告费用 - 促销费用 - 退货损失

同时输出：

* 销量变化；

* 广告订单变化；

* 自然排名变化；

* TACOS变化；

* 库存消耗速度；

* 缺货时间；

* 总利润；

* 现金流占用；

* 最大风险。

### 第四层：Switchback真实验证

预测只是模型判断，不能直接当成事实。

选择最优方案后，可以对一小部分ASIN、关键词或时间段进行实验：

* 时间段1：维持原策略；

* 时间段2：使用新策略；

* 时间段3：恢复原策略；

* 时间段4：再次使用新策略。

通过真实结果修正预测模型。

Amazon Science公开说明，时间切换实验需要处理上一阶段对下一阶段的残留影响，例如广告、销量或推荐权重可能不会立即恢复。因此需要设置过渡期。[Amazon Science Switchback介绍](https://www.amazon.science/blog/the-science-of-price-experiments-in-the-amazon-store)

### 第五层：执行与复盘

系统最终输出：

* 推荐方案；

* 不推荐方案；

* 预计增量利润；

* 最大可承受预算；

* 执行条件；

* 风险停止线；

* 复核周期；

* 预测值与实际值偏差；

* 下次模型修正参数。

## 五、可以优先建设的六类模拟器

| 优先级 | 模拟器 | 核心问题 |
|----|----|----|
| P0 | 广告预算模拟器 | 加预算后是增加订单，还是只抬高ACOS？ |
| P0 | 价格与促销模拟器 | 降价、Coupon和BD哪个增量利润最高？ |
| P0 | 库存补货模拟器 | 补多少、何时补、什么时候可能缺货？ |
| P1 | FBA/AWD分配模拟器 | 不同库存比例对费用和可售率有什么影响？ |
| P1 | 新品增长模拟器 | 达到目标自然排名需要多少预算和订单？ |
| P1 | 竞争攻防模拟器 | 对手降价、涨广告或做BD时怎么应对？ |

其中最适合你们现在先做的是“广告+价格+库存”三者联动：

> 广告增加会提高销量，销量增加会加快库存消耗；库存不足又会限制广告放量；价格变化会同时改变CVR、利润率和广告CPC上限。

这三个模块不能分别孤立计算。

## 六、系统需要建立统一的Scenario数据结构

每次模拟都保存以下字段：

| 字段 | 含义 |
|----|----|
| Scenario ID | 场景编号 |
| ASIN/SKU | 模拟对象 |
| Baseline | 当前经营基线 |
| Decision Variables | 准备改变的变量 |
| Time Horizon | 预测周期 |
| Assumptions | 价格弹性、CVR、CPC等假设 |
| Constraints | 库存、现金流、毛利和预算限制 |
| Predicted Result | 模型预测结果 |
| Confidence Range | 预测区间 |
| Recommended Action | 推荐动作 |
| Guardrail | 风险停止线 |
| Experiment Design | 后续验证方案 |
| Actual Result | 实际执行结果 |
| Prediction Error | 预测误差 |
| Model Update | 模型修正记录 |

这样才能让系统不断学习，而不是每次重新计算一次就结束。

## 七、需要保持的一个清醒判断

Amazon的Scenario Modeling值得使用，但Amazon模型的优化目标不一定完全等于卖家的最终目标。

Amazon可能更关注：

* 整体仓储效率；

* FBA库存健康；

* AWD采用率；

* 配送效率；

* 包装和物流成本；

* 平台网络稳定性。

卖家更关注：

* 单件贡献利润；

* 现金流；

* 库存风险；

* 广告效率；

* 自然排名；

* 长期品牌价值。

因此最好的策略不是完全依赖Amazon预测，而是：

> 使用Amazon Scenario Modeling作为平台视角的预测，再用天机AI建立卖家利润视角的独立模型，比较两个模型的差异。

最终的新思路可以概括为：

> Amazon正在把卖家运营从“看报表、凭经验做决策”，升级为“先模拟、再实验、后执行、持续校准”。天机AI可以进一步建立以ASIN为单位的经营数字孪生，把广告、价格、Listing、库存、供应链和利润放进同一个场景模型，再使用Switchback或小范围测试验证预测，最终形成跨境电商的AI决策操作系统。
