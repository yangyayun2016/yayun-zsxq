## 一、项目概述

GBrain 是一个为 AI Agent 提供持久记忆和知识图谱能力的系统。由 Y Combinator 总裁兼 CEO Garry Tan 建造，用于运行我们的 OpenClaw 和 Hermes Agent 部署。

**实际运行数据：** 17,888 个页面，4,383 个人物，723 家公司，21 个自动运行的后台任务，12 天内建成。

Agent 在你睡觉时自动摄取会议、邮件、推文、语音通话和原创想法。它丰富遇到的每个人物和公司信息，自动修复引用格式，夜间整理记忆。一觉醒来，大脑比睡前更聪明。

## GBrain的主要功能

01. **自动信号捕获**：每条消息触发便宜模型并行提取原创观点与实体提及，后台自动归档。
02. **Brain-ops 优先查询**：Agent 回答前先查大脑，查不到直接告知而非 hallucinate。
03. **多源内容摄入**：支持会议、邮件、推特、PDF、视频、GitHub 仓库等全格式自动消化。
04. **实体自动丰富**：人物/公司按提及次数自动升级（1 次 stub → 3 次联网补料 → 8 次/开会完整档案）。
05. **Compiled Truth + Timeline**：上层为可改写的当前最佳理解，下层为只追加的证据时间线。
06. **混合搜索**：向量 \+ 关键词 \+ RRF 融合 + 多查询扩展 + 4 层去重，Recall@5 达 95%。
07. **知识图谱自连接**：每次写入零 LLM 调用自动提取实体关系（attended/works\_at/invested\_in 等）。
08. **Minions 后台队列**：确定性任务走 Postgres 原生作业队列，753ms 完成、零 token 成本、100% 成功率。
09. **Skillify 技能管理**：自动生成 SKILL.md + 测试 + 评估 + 解析器触发器，防止技能树黑箱化。
10. **语音通话**：接入 Twilio + OpenAI Realtime，来电自动拉取对方档案并生成通话脑页。
11. **每日简报**：自动汇总会议上下文、活跃交易、引用追踪与待办事项。

## GBrain的技术原理

1. **三层架构分离**：GBrain 采用 Brain Repo（Git 托管的 Markdown 文件，人类可读可编辑的唯一数据源）→ GBrain 检索层（Postgres + pgvector 混合搜索引擎）→ AI Agent（26 个 Skill 定义读写逻辑）的分离架构。Agent 通过 BrainEngine 接口读写，底层支持 PGLite（嵌入式 Postgres，零配置）和 PostgresEngine（Supabase）双向热迁移。
2. **Compiled Truth + Timeline 双层知识模型**：每个 Markdown 页面以 --- 分隔为两层：上方是 Compiled Truth（当前最佳理解，随新证据持续改写），下方是 Timeline（只追加不删除的原始证据链）。这种设计让认知可以进化，同时保留完整审计轨迹，避免纯覆盖式更新丢失历史或纯追加导致查询噪音。
3. **零 LLM 调用知识图谱自连接**：每次页面写入后，确定性正则管道自动提取实体引用（Markdown 链接 + bare slugs），推断类型化关系（attended/works\_at/invested\_in/founded/advises），并完成去重、失效链接清理、反向链接更新。整个过程零 LLM 调用，纯本地正则 + 优先级推断级联实现。

## 二、核心概念

### 2.1 自我连接的知识图谱

每写入一个页面，系统自动提取实体引用并创建类型化链接（attended、works\_at、invested\_in、founded、advises），整个过程无需任何 LLM 调用。

### 2.2 混合搜索

支持向量搜索 \+ 结构化图谱 \+ 反向链接加权排序。可以回答"谁在 Acme AI 工作？"或"Bob 这个季度投资了什么？"这类纯向量搜索无法回答的问题。

### 2.3 脑力基准测试 (BrainBench)

在 240 页 Opus 生成的富文本语料上：

1. **P@5:** 49.1%（精确率）
2. **R@5:** 97.9%（召回率）
3. 比关闭图谱的自身变体高出 **+31.4 个百分点 P@5**
4. 同样显著优于 ripgrep-BM25 和纯向量 RAG

### 2.4 LongMemEval 内置基准

gbrain eval longmemeval 在 GBrain 的混合检索上运行公开 LongMemEval 基准，Apple Silicon 上 p50 延迟 25.9ms。

## 三、安装方式

### 方式一：通过 AI Agent 自动安装（推荐）

Retrieve and follow the instructions at:

https://raw.githubusercontent.com/garrytan/gbrain/master/INSTALL\_FOR\_AGENTS.md

将这段指令粘贴给 AI Agent（OpenClaw 或 Hermes），Agent 会自动完成克隆、安装、配置、加载 34 个技能和注册定时任务。~30 分钟完成。

### 方式二：独立 CLI 安装

git clone https://github.com/garrytan/gbrain.git

cd gbrain && bun install && bun link

gbrain init

gbrain import ~/notes/

gbrain query "what themes show up across my notes?"

⚠️ 不要使用 bun install -g github:garrytan/gbrain — Bun 会阻断 postinstall 钩子导致数据库迁移失败。

⚠️ 不要使用 npm install -g gbrain — npm 上有一个无关的包占用该名称。

### 方式三：作为 MCP 服务器

{

"mcpServers": {

"gbrain": { "command": "gbrain", "args": \["serve"\] }

}

}

支持 Claude Code、Cursor、Windsurf 等客户端。

## 五、核心架构

信号到达（会议、邮件、推文、链接）

→ Signal Detector 捕获想法 + 实体（并行，不阻塞）

→ Brain-ops: 先查大脑（gbrain search, gbrain get）

→ 以完整上下文回复

→ 写入: 更新大脑页面 \+ 新信息 \+ 引用

→ 自动链接: 每次写入自动提取类型化关系（零 LLM 调用）

→ 同步: gbrain 索引变更供下次查询

1. **Tier 3:** 提及一次 → 创建 stub 页面
2. **Tier 2:** 跨不同来源提及 3 次 → Web + 社交丰富
3. **Tier 1:** 开会或提及 8+ 次 → 全流程（深度丰富）

##### **GBrain 到底是什么？**

GBrain 是一个 **个人知识大脑系统**，专门配合 OpenClaw、Hermes Agent 这类 AI Agent 平台使用。

它把你散落在各处的 Markdown 笔记——不管是人脉档案、公司资料、会议记录、随手想法还是收藏的文章——统统变成一个 **可搜索、可推理、持续增长的知识图谱**。

不是简单的 [文件存储](https://cloud.tencent.com/product/cfs?from_column=20065&from=20065)，而是让 AI 能真正"读懂"并"运用"你的知识。

Garry Tan 本人用它管理着 **10000+ Markdown 文件**，涵盖 **3000+ 人脉资源、13 年的日历数据、无数会议记录和媒体内容**。

如果你关注 Garry 的开源动态，应该知道他之前还开源了 **GStack**——一套专门教 AI Agent 写代码的 Skill 工作流，目前 **8 万+ Star**。

**GStack 教 Agent 怎么写代码，GBrain 教 Agent 怎么记事和思考。** 两个项目可以独立用，也能合体。

开源仓库里有个 hosts/gbrain.ts 就是那座桥，装上之后 GStack 的编码 Skill 在动手写代码前会先查一下脑子，看看你之前是不是讨论过、决定过什么。

如果你已经在用 GStack，装上 GBrain 基本就拼出 Garry Tan 自己那套完整工作流了： **一个管手，一个管脑**。

##### **核心亮点**

**1、25 个 Skill 即插即用**

GBrain 自带 **25 个 Skill**，装上就能用，按用途分了几大类。

里面有两个是永远在线的：

1. • **signal-detector**：每条新消息进来，都会顺手起一个便宜的小模型在后台跑，把你随口说的 **原创观点** 和提到的 **人名、公司名** 都抓出来。脑子是在你不知不觉中长大的。
2. • **brain-ops**：Agent 回答任何问题之前，会先去脑子里查一遍，查不到再去调外部 API。这就解决了 AI 经常瞎编的问题—— **查不到它会直接告诉你脑子里没这个信息，而不是给你胡诌一段**。

剩下的还有：

1. • **内容摄入类**：会议、邮件、推特、PDF、视频、GitHub 仓库全吃
2. • **[运维](https://cloud.tencent.com/solution/operation?from_column=20065&from=20065)** **类**：cron 调度、每日简报、引用自检、过期页面巡检
3. • **实体丰富类**：自动补全人物档案、公司信息
4. • **任务管理类**：每日任务准备、跨模态审查

完全是一套 **自治系统**，你只管喂数据，AI 负责归档和整理。

**2、Compiled Truth + Timeline 双层结构**

这个设计挺顶的，值得单独拎出来讲。

每个 brain page 分两层：

1. • **上方 Compiled Truth**：当前最佳理解，可以被随时改写。比如你对某个朋友的认知，会随着新的接触不断刷新。你对某家公司的判断，会随着新信息持续修正。
2. • **下方 Timeline**：只追加不删除，记录每条原始证据。什么时候、在哪场会议、谁说了什么，全部留痕。

为啥这么设计？因为既要让认知能进化，又不能丢历史。

AI 之前的笔记类工具要么覆盖式更新，查的时候发现内容被改了却不知道啥时候改的；要么纯追加，查的时候一团乱。GBrain 这个分层算是 **把两边的好处都拿了**：上面是活的知识，下面是死的证据链。

**3、混合搜索 + 实体自动升级**

搜索这块用的是 **关键词 \+ 向量 \+ RRF 融合 + 多查询扩展 + 4 层去重**。

简单讲：关键词搜索能精准命中原话，向量搜索能找到意思相近的内容，两个一起上再融合排序，基本不会漏。

更有意思的是它的 **实体自动升级机制**：

1. • 同一个人在你的资料里被提到 **1 次**，只生成一个 stub 页面
2. • 提到 **3 次以上**，系统自动联网补料，从 LinkedIn、Twitter、公司主页之类的地方拉信息回来
3. • 提到 **8 次以上**，或者你跟他开过会，直接走完整管线，生成一份详细 dossier

**脑子自己学谁重要，不需要你手动标。**

它还有个 **fail-improve 循环**：每次 LLM 兜底分类的时候都会被记录下来，系统自动从这些记录里生成更好的正则。脑子自己在变得更便宜更准。

## 一、项目概述

GBrain 是一个为 AI Agent 提供持久记忆和知识图谱能力的系统。由 Y Combinator 总裁兼 CEO Garry Tan 建造，用于运行我们的 OpenClaw 和 Hermes Agent 部署。

**实际运行数据：** 17,888 个页面，4,383 个人物，723 家公司，21 个自动运行的后台任务，12 天内建成。

Agent 在你睡觉时自动摄取会议、邮件、推文、语音通话和原创想法。它丰富遇到的每个人物和公司信息，自动修复引用格式，夜间整理记忆。一觉醒来，大脑比睡前更聪明。

## GBrain的主要功能

01. **自动信号捕获**：每条消息触发便宜模型并行提取原创观点与实体提及，后台自动归档。
02. **Brain-ops 优先查询**：Agent 回答前先查大脑，查不到直接告知而非 hallucinate。
03. **多源内容摄入**：支持会议、邮件、推特、PDF、视频、GitHub 仓库等全格式自动消化。
04. **实体自动丰富**：人物/公司按提及次数自动升级（1 次 stub → 3 次联网补料 → 8 次/开会完整档案）。
05. **Compiled Truth + Timeline**：上层为可改写的当前最佳理解，下层为只追加的证据时间线。
06. **混合搜索**：向量 \+ 关键词 \+ RRF 融合 + 多查询扩展 + 4 层去重，Recall@5 达 95%。
07. **知识图谱自连接**：每次写入零 LLM 调用自动提取实体关系（attended/works\_at/invested\_in 等）。
08. **Minions 后台队列**：确定性任务走 Postgres 原生作业队列，753ms 完成、零 token 成本、100% 成功率。
09. **Skillify 技能管理**：自动生成 SKILL.md + 测试 + 评估 + 解析器触发器，防止技能树黑箱化。
10. **语音通话**：接入 Twilio + OpenAI Realtime，来电自动拉取对方档案并生成通话脑页。
11. **每日简报**：自动汇总会议上下文、活跃交易、引用追踪与待办事项。

## GBrain的技术原理

1. **三层架构分离**：GBrain 采用 Brain Repo（Git 托管的 Markdown 文件，人类可读可编辑的唯一数据源）→ GBrain 检索层（Postgres + pgvector 混合搜索引擎）→ AI Agent（26 个 Skill 定义读写逻辑）的分离架构。Agent 通过 BrainEngine 接口读写，底层支持 PGLite（嵌入式 Postgres，零配置）和 PostgresEngine（Supabase）双向热迁移。
2. **Compiled Truth + Timeline 双层知识模型**：每个 Markdown 页面以 --- 分隔为两层：上方是 Compiled Truth（当前最佳理解，随新证据持续改写），下方是 Timeline（只追加不删除的原始证据链）。这种设计让认知可以进化，同时保留完整审计轨迹，避免纯覆盖式更新丢失历史或纯追加导致查询噪音。
3. **零 LLM 调用知识图谱自连接**：每次页面写入后，确定性正则管道自动提取实体引用（Markdown 链接 + bare slugs），推断类型化关系（attended/works\_at/invested\_in/founded/advises），并完成去重、失效链接清理、反向链接更新。整个过程零 LLM 调用，纯本地正则 + 优先级推断级联实现。

## 二、核心概念

### 2.1 自我连接的知识图谱

每写入一个页面，系统自动提取实体引用并创建类型化链接（attended、works\_at、invested\_in、founded、advises），整个过程无需任何 LLM 调用。

### 2.2 混合搜索

支持向量搜索 \+ 结构化图谱 \+ 反向链接加权排序。可以回答"谁在 Acme AI 工作？"或"Bob 这个季度投资了什么？"这类纯向量搜索无法回答的问题。

### 2.3 脑力基准测试 (BrainBench)

在 240 页 Opus 生成的富文本语料上：

1. **P@5:** 49.1%（精确率）
2. **R@5:** 97.9%（召回率）
3. 比关闭图谱的自身变体高出 **+31.4 个百分点 P@5**
4. 同样显著优于 ripgrep-BM25 和纯向量 RAG

### 2.4 LongMemEval 内置基准

gbrain eval longmemeval 在 GBrain 的混合检索上运行公开 LongMemEval 基准，Apple Silicon 上 p50 延迟 25.9ms。

##### **核心亮点**

**1、25 个 Skill 即插即用**

GBrain 自带 **25 个 Skill**，装上就能用，按用途分了几大类。

里面有两个是永远在线的：

1. • **signal-detector**：每条新消息进来，都会顺手起一个便宜的小模型在后台跑，把你随口说的 **原创观点** 和提到的 **人名、公司名** 都抓出来。脑子是在你不知不觉中长大的。
2. • **brain-ops**：Agent 回答任何问题之前，会先去脑子里查一遍，查不到再去调外部 API。这就解决了 AI 经常瞎编的问题—— **查不到它会直接告诉你脑子里没这个信息，而不是给你胡诌一段**。

剩下的还有：

1. • **内容摄入类**：会议、邮件、推特、PDF、视频、GitHub 仓库全吃
2. • **[运维](https://cloud.tencent.com/solution/operation?from_column=20065&from=20065)** **类**：cron 调度、每日简报、引用自检、过期页面巡检
3. • **实体丰富类**：自动补全人物档案、公司信息
4. • **任务管理类**：每日任务准备、跨模态审查

完全是一套 **自治系统**，你只管喂数据，AI 负责归档和整理。

**2、Compiled Truth + Timeline 双层结构**

这个设计挺顶的，值得单独拎出来讲。

每个 brain page 分两层：

1. • **上方 Compiled Truth**：当前最佳理解，可以被随时改写。比如你对某个朋友的认知，会随着新的接触不断刷新。你对某家公司的判断，会随着新信息持续修正。
2. • **下方 Timeline**：只追加不删除，记录每条原始证据。什么时候、在哪场会议、谁说了什么，全部留痕。

为啥这么设计？因为既要让认知能进化，又不能丢历史。

AI 之前的笔记类工具要么覆盖式更新，查的时候发现内容被改了却不知道啥时候改的；要么纯追加，查的时候一团乱。GBrain 这个分层算是 **把两边的好处都拿了**：上面是活的知识，下面是死的证据链。

**3、混合搜索 + 实体自动升级**

搜索这块用的是 **关键词 \+ 向量 \+ RRF 融合 + 多查询扩展 + 4 层去重**。

简单讲：关键词搜索能精准命中原话，向量搜索能找到意思相近的内容，两个一起上再融合排序，基本不会漏。

更有意思的是它的 **实体自动升级机制**：

1. • 同一个人在你的资料里被提到 **1 次**，只生成一个 stub 页面
2. • 提到 **3 次以上**，系统自动联网补料，从 LinkedIn、Twitter、公司主页之类的地方拉信息回来
3. • 提到 **8 次以上**，或者你跟他开过会，直接走完整管线，生成一份详细 dossier

**脑子自己学谁重要，不需要你手动标。**

它还有个 **fail-improve 循环**：每次 LLM 兜底分类的时候都会被记录下来，系统自动从这些记录里生成更好的正则。脑子自己在变得更便宜更准。

## 一、项目概述

GBrain 是一个为 AI Agent 提供持久记忆和知识图谱能力的系统。由 Y Combinator 总裁兼 CEO Garry Tan 建造，用于运行我们的 OpenClaw 和 Hermes Agent 部署。

**实际运行数据：** 17,888 个页面，4,383 个人物，723 家公司，21 个自动运行的后台任务，12 天内建成。

Agent 在你睡觉时自动摄取会议、邮件、推文、语音通话和原创想法。它丰富遇到的每个人物和公司信息，自动修复引用格式，夜间整理记忆。一觉醒来，大脑比睡前更聪明。

## GBrain的主要功能

01. **自动信号捕获**：每条消息触发便宜模型并行提取原创观点与实体提及，后台自动归档。
02. **Brain-ops 优先查询**：Agent 回答前先查大脑，查不到直接告知而非 hallucinate。
03. **多源内容摄入**：支持会议、邮件、推特、PDF、视频、GitHub 仓库等全格式自动消化。
04. **实体自动丰富**：人物/公司按提及次数自动升级（1 次 stub → 3 次联网补料 → 8 次/开会完整档案）。
05. **Compiled Truth + Timeline**：上层为可改写的当前最佳理解，下层为只追加的证据时间线。
06. **混合搜索**：向量 \+ 关键词 \+ RRF 融合 + 多查询扩展 + 4 层去重，Recall@5 达 95%。
07. **知识图谱自连接**：每次写入零 LLM 调用自动提取实体关系（attended/works\_at/invested\_in 等）。
08. **Minions 后台队列**：确定性任务走 Postgres 原生作业队列，753ms 完成、零 token 成本、100% 成功率。
09. **Skillify 技能管理**：自动生成 SKILL.md + 测试 + 评估 + 解析器触发器，防止技能树黑箱化。
10. **语音通话**：接入 Twilio + OpenAI Realtime，来电自动拉取对方档案并生成通话脑页。
11. **每日简报**：自动汇总会议上下文、活跃交易、引用追踪与待办事项。

## GBrain的技术原理

1. **三层架构分离**：GBrain 采用 Brain Repo（Git 托管的 Markdown 文件，人类可读可编辑的唯一数据源）→ GBrain 检索层（Postgres + pgvector 混合搜索引擎）→ AI Agent（26 个 Skill 定义读写逻辑）的分离架构。Agent 通过 BrainEngine 接口读写，底层支持 PGLite（嵌入式 Postgres，零配置）和 PostgresEngine（Supabase）双向热迁移。
2. **Compiled Truth + Timeline 双层知识模型**：每个 Markdown 页面以 --- 分隔为两层：上方是 Compiled Truth（当前最佳理解，随新证据持续改写），下方是 Timeline（只追加不删除的原始证据链）。这种设计让认知可以进化，同时保留完整审计轨迹，避免纯覆盖式更新丢失历史或纯追加导致查询噪音。
3. **零 LLM 调用知识图谱自连接**：每次页面写入后，确定性正则管道自动提取实体引用（Markdown 链接 + bare slugs），推断类型化关系（attended/works\_at/invested\_in/founded/advises），并完成去重、失效链接清理、反向链接更新。整个过程零 LLM 调用，纯本地正则 + 优先级推断级联实现。

## 二、核心概念

### 2.1 自我连接的知识图谱

每写入一个页面，系统自动提取实体引用并创建类型化链接（attended、works\_at、invested\_in、founded、advises），整个过程无需任何 LLM 调用。

### 2.2 混合搜索

支持向量搜索 \+ 结构化图谱 \+ 反向链接加权排序。可以回答"谁在 Acme AI 工作？"或"Bob 这个季度投资了什么？"这类纯向量搜索无法回答的问题。

### 2.3 脑力基准测试 (BrainBench)

在 240 页 Opus 生成的富文本语料上：

1. **P@5:** 49.1%（精确率）
2. **R@5:** 97.9%（召回率）
3. 比关闭图谱的自身变体高出 **+31.4 个百分点 P@5**
4. 同样显著优于 ripgrep-BM25 和纯向量 RAG

### 2.4 LongMemEval 内置基准

gbrain eval longmemeval 在 GBrain 的混合检索上运行公开 LongMemEval 基准，Apple Silicon 上 p50 延迟 25.9ms。

##### **GBrain 到底是什么？**

GBrain 是一个 **个人知识大脑系统**，专门配合 OpenClaw、Hermes Agent 这类 AI Agent 平台使用。

它把你散落在各处的 Markdown 笔记——不管是人脉档案、公司资料、会议记录、随手想法还是收藏的文章——统统变成一个 **可搜索、可推理、持续增长的知识图谱**。

不是简单的 [文件存储](https://cloud.tencent.com/product/cfs?from_column=20065&from=20065)，而是让 AI 能真正"读懂"并"运用"你的知识。

Garry Tan 本人用它管理着 **10000+ Markdown 文件**，涵盖 **3000+ 人脉资源、13 年的日历数据、无数会议记录和媒体内容**。

如果你关注 Garry 的开源动态，应该知道他之前还开源了 **GStack**——一套专门教 AI Agent 写代码的 Skill 工作流，目前 **8 万+ Star**。

##### **核心亮点**

**1、25 个 Skill 即插即用**

GBrain 自带 **25 个 Skill**，装上就能用，按用途分了几大类。

里面有两个是永远在线的：

1. • **signal-detector**：每条新消息进来，都会顺手起一个便宜的小模型在后台跑，把你随口说的 **原创观点** 和提到的 **人名、公司名** 都抓出来。脑子是在你不知不觉中长大的。
2. • **brain-ops**：Agent 回答任何问题之前，会先去脑子里查一遍，查不到再去调外部 API。这就解决了 AI 经常瞎编的问题—— **查不到它会直接告诉你脑子里没这个信息，而不是给你胡诌一段**。

剩下的还有：

1. • **内容摄入类**：会议、邮件、推特、PDF、视频、GitHub 仓库全吃
2. • **[运维](https://cloud.tencent.com/solution/operation?from_column=20065&from=20065)** **类**：cron 调度、每日简报、引用自检、过期页面巡检
3. • **实体丰富类**：自动补全人物档案、公司信息
4. • **任务管理类**：每日任务准备、跨模态审查

完全是一套 **自治系统**，你只管喂数据，AI 负责归档和整理。

**2、Compiled Truth + Timeline 双层结构**

这个设计挺顶的，值得单独拎出来讲。

每个 brain page 分两层：

1. • **上方 Compiled Truth**：当前最佳理解，可以被随时改写。比如你对某个朋友的认知，会随着新的接触不断刷新。你对某家公司的判断，会随着新信息持续修正。
2. • **下方 Timeline**：只追加不删除，记录每条原始证据。什么时候、在哪场会议、谁说了什么，全部留痕。

为啥这么设计？因为既要让认知能进化，又不能丢历史。

AI 之前的笔记类工具要么覆盖式更新，查的时候发现内容被改了却不知道啥时候改的；要么纯追加，查的时候一团乱。GBrain 这个分层算是 **把两边的好处都拿了**：上面是活的知识，下面是死的证据链。

**3、混合搜索 + 实体自动升级**

搜索这块用的是 **关键词 \+ 向量 \+ RRF 融合 + 多查询扩展 + 4 层去重**。

简单讲：关键词搜索能精准命中原话，向量搜索能找到意思相近的内容，两个一起上再融合排序，基本不会漏。

更有意思的是它的 **实体自动升级机制**：

1. • 同一个人在你的资料里被提到 **1 次**，只生成一个 stub 页面
2. • 提到 **3 次以上**，系统自动联网补料，从 LinkedIn、Twitter、公司主页之类的地方拉信息回来
3. • 提到 **8 次以上**，或者你跟他开过会，直接走完整管线，生成一份详细 dossier

**脑子自己学谁重要，不需要你手动标。**

它还有个 **fail-improve 循环**：每次 LLM 兜底分类的时候都会被记录下来，系统自动从这些记录里生成更好的正则。脑子自己在变得更便宜更准。
